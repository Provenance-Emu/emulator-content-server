# Catalog, storage, auth, server

- Migrations are append-only numbered SQL. Never edit one that has shipped. The catalog must open cleanly twice and keep existing rows; a schema version mismatch is a hard error. Use the `add-migration` skill.
- Order of work in a request: authenticate, decide access with the pure ACL function, then touch the filesystem. `requireVisibleAsset` distinguishes 404 from 403 so hidden items cannot be probed. Do not add a route that opens a blob before the decision.
- `resolveInside` is the only way to turn operator or client input into a path.
- SHA-256 is blob identity. Blobs are immutable. MD5 and CRC are compatibility fields.
- Writes honour `If-Match: "rev-N"` and `Idempotency-Key`. Catalog mutations append to the change cursor; mark restricted assets `sensitive`.
- Deleting is the dangerous verb. Know whether a path removes catalog rows, bytes on disk, or both before you change it, and keep registered server folders read-only unless the feature is explicitly about moving files.
- Never log bootstrap tokens, bearer tokens, passwords, or authorization headers. Audit details carry no raw tokens. No credential in a query string.
- Operator-installed provider and manager modules run only in the plugin process (`apps/plugins`), never in the HTTP process.
- Tests use generated bytes. No ROM, BIOS, disc, or save fixtures.
- One proportionate review (`ecs-reviewer`) for auth, storage, protocol, or concurrency changes. Not for routine edits.
