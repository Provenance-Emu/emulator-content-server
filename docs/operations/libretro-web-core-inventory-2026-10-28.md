# Libretro Emscripten core inventory (2026-10-28)

This snapshot records the official web-player Emscripten artifacts evaluated for the browser player catalog. The machine-readable receipt with each loader/WASM URL, byte count, SHA-256 pin, core-info metadata, smoke result, and unavailable-path check is [web-core-inventory-2026-10-28.json](./web-core-inventory-2026-10-28.json).

## Method and scope

The official selector at [`web.libretro.com/core_list.js`](https://web.libretro.com/core_list.js) listed 88 core names in this snapshot. I fetched 88 loader/WASM name pairs from the same official host; 87 pairs fit the configured per-file caps and passed an opaque-origin Chromium startup probe. The probe used a sandboxed frame with `sandbox="allow-scripts"`, imported each default ESM factory, provided `wasmBinary`, `noInitialRun`, `noExitRuntime`, and `locateFile`, checked `FS.mkdirTree`, `FS.writeFile`, `FS.readFile`, and `callMain`, then performed a small MEMFS round-trip. It did not load or run game content. It does not establish graphics, audio, input, save, BIOS, compatibility, or performance behavior.

The fetch/hash/factory audit can be repeated with `pnpm exec node scripts/browser-core/audit-libretro-web.mjs`. It writes only JS/WASM artifacts and reports under the dated external `~/.cache/ecs-wasm-inventory-YYYY-MM-DD` directory; it does not write core binaries into the repository.

All advertised entries use the `retroarch-emscripten-esm` runtime, MEMFS, no thread/worker requirement, and `saveCompletion: none`. The app continues to run the player inside its opaque credential-isolated iframe. No game ROM, disc, save, or BIOS data was downloaded or included. The core info may list firmware requirements; those notes are preserved in the JSON receipt and should be checked when evaluating a specific core.

The official `web.libretro.com` artifact paths are mutable. Each entry pins the exact captured size and SHA-256; installation rejects different bytes. A future upstream replacement can therefore make an install unavailable until the pins are deliberately refreshed. The official daily RetroArch archive is date-named, but it is a large bundle containing unrelated demo/game data and does not provide a source commit manifest. No per-core stable release asset or exact source-commit mapping was found. Source repositories below are provenance links; they are not asserted to be the exact commits used by the web artifact.

## Game-data staging limits

The catalog retains pins for 35 common profiles. Thirty-one are eligible for experimental one-click installation; four engine profiles are withheld until their data adapters work: [PrBoom requires prboom.wad](https://docs.libretro.com/library/prboom/), [ECWolf requires ecwolf.pk3 plus game companions](https://docs.libretro.com/library/ecwolf/), [TyrQuake uses the id1/pak0.pak directory layout](https://docs.libretro.com/library/tyrquake/), and vitaQuake2 folder staging remains unverified. Factory startup alone cannot establish these layouts. The installer shows each concrete limitation instead of enabling these known-incomplete engines.

Companion-media layouts such as CUE, GDI, CCD, and M3U are omitted where this player cannot stage their referenced files. FDS and CD-disc systems are not advertised because their firmware and companion-file requirements are not supported here. Arcade ZIP files must be self-contained; separate parent BIOS sets cannot be staged. ## Exclusions and blockers

- **ScummVM**: its official WASM is 75,686,701 bytes, above the 64 MiB limit.
- **Nintendo 64:** `parallel_n64` exists at an old web path, but its loader is a classic global-`Module` script without an ESM default factory; the WASM could not be fully fetched and no exact pair pin was recorded. `mupen64plus_next` paths returned 404. No N64 profile is advertised.
- **PS1:** PCSX ReARMed's live official pair passed the same factory probe, but the catalog omits it to avoid duplicating the separately source-built PS1 profile being integrated.
- **PS2, Dolphin/GameCube, and Azahar/3DS:** the checked official web-player loader and WASM paths returned 404. No compatible upstream browser artifact was found.
- **Vectrex (`vecx`)** is listed by the official selector and passed the factory test, but core info declares OpenGL Core 3.3 hardware rendering by default. It is excluded from the software-rendered catalog; its optional software-renderer route was not validated.
- Cores without a direct supported Provenance system mapping, cores with hardware-rendering requirements, and profiles needing companion files that the player cannot stage are not advertised by this catalog.

Some included cores declare optional or required BIOS/core-data files or restricted licenses (including non-commercial licenses). Their source, license, firmware notes, and full upstream extension list are in the JSON receipt and linked core-info record. Startup success is not a claim that those files are present or that a game will run.
