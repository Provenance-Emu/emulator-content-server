# Browser mappings and unified controller layouts

The player owns its input editor and rendering. The first supported adapter is gated to the verified FCEUmm loader/WASM pair in `apps/web/src/player/input-model.ts`; other builds keep native input and explain why custom mappings are unavailable. A timed-out adapter restores the guest's native gamepad getter. No core rebuild, dependency, API or sandbox/CSP change is included.

## Shared layout document

`ControllerLayout` (`apps/web/src/player/layout.ts`) is a versioned, bounded document with separate portrait/landscape representations. Each representation has a reference size, a game screen rectangle, logical controls, visual frames, optional hit insets and opacity. A visual is either an original procedural shape/text label or an asset ID. Optional artwork layers and normalized source-screen crop frames survive validation/serialization. Asset IDs cannot contain paths or URLs. A single contain transform positions both the game mount and controls; minimum touch regions are separate from drawn size.

Compact and standard presets generate this same document. There is no separate built-in skin format to replace later. The current editor renders procedural controls; image IDs/crop metadata are groundwork for the later importer, not a claim that imported artwork/PDFs render today. This pass accepts one game screen per representation. Future Delta conversion needs an asset resolver, bounded archive parser, representation/system-action adapter, supported image/PDF rendering and explicit unsupported states. See [SkinKit research](browser-player-skins-research-2026-10-30.md).

Play supports independent pointers, D-pad sliding/diagonals and left/right sticks. Reference shows current bindings. Edit suspends input while the game continues, with drag/resize handles, numeric geometry/opacity, action changes, add/remove, undo, presets and apply/cancel. Overlay fills the reference plane with the game; underlay reserves game space above the controls. Portrait and landscape edits are independent. Release controls remains reachable outside the editable layer. Screenshots/state thumbnails still contain game/shader pixels only.

## Input and persistence

The first-party module runs inside the existing opaque guest. It saves the physical `getGamepads` getter, then exposes four standard virtual pads to the native rwebpad driver. Each physical connection is explicitly assigned to a port; only bounded model descriptors are remembered, never connection indices. Keyboard codes, mouse buttons/wheel, physical buttons/axes and host touches contribute independent sources. Live highlights and stick axes help test mappings. Duplicate bindings are rejected before applying. Keyboard and mouse native passthrough are explicit modes; native pointer movement remains the core's existing behavior.

Touch snapshots use a separate MessagePort message type, bypassing waiting filesystem/save/settings RPCs. The engine ORs digital sources, neutralizes opposing directions, uses the greatest analog magnitude (equal opposing values cancel), preserves short presses until a native poll, and releases abandoned input after 750 ms without a host heartbeat. Sources, packets, axes, controls and stored JSON have explicit limits. Focus loss, hidden pages, pointer cancellation, disconnects, mapping/editor changes and teardown release affected input. Re-entry requires neutral/fresh interaction. Guest iframe blur clears guest keys/mouse without cancelling a host finger still playing.

Preferences have a distinct `ecs.input.v1` namespace scoped to origin, exact core build and optional game. Remember saves only explicitly edited fields, preserving inherited core defaults. Corrupt/unavailable storage keeps defaults usable and reports a warning. Conflicting newer inherited bindings keep the last valid scope. Game bytes, saves, tokens and event history are never stored here. Clearing stored defaults does not restart the running game. Pending save uploads retain retry/export controls; release remains enabled.

## Acceptance

Focused checks cover layout validation/shared transforms/equal insets, asset/crop metadata round trips, source isolation, tap latching, neutral rearming/watchdog/cancellation, bounded pending sources, preference scopes/corruption/private storage, editor undo/cancel, model-only persistence and fallback restoration.

Browser acceptance uses the external pinned FCEUmm artifacts and the repository's original generated NES program, with generated artifacts outside Git. Chromium, desktop WebKit and iPhone-profile WebKit verify the independent realtime bridge during a busy RPC, watchdog releases, synthetic controller neutral capture/dead zones/inversion/disconnect, mouse pulses and keyboard suppression. Real-core acceptance checks remapped input changes game pixels while capture, native state previews/load, saves, settings, shader controls and failed-upload recovery keep working. Expanded real-core checks cover remapped keyboard/mouse/controller/touch input, Chromium concurrent touches, stick cancellation, layout geometry/placement/undo/cancel/apply and persisted game overrides. One focused review found four input lifecycle/persistence/inversion issues; each was fixed with a failing regression followed by a passing check.

These are browser profiles and synthetic device snapshots. Physical Mac Safari/iPhone/controller pairing, notch/safe-area rotation, sustained input latency and audio quality still need hardware acceptance. Four virtual ports do not establish multiplayer support for every core. Delta import, emuskins browsing, artwork/PDF rendering, pointer lock, HID/MIDI and sensors remain follow-ups.

Validation commands: `pnpm --filter @ecs/web check` (296 tests, zero Svelte warnings), `pnpm ui`, the focused `playwright.player.config.ts` real-core/input acceptance projects (`chromium`, `webkit`, `iphone-webkit`), and existing sandbox/settings/capture browser regressions. Package boundaries and secret/fixture scan also pass. Operator core artifacts, generated game/save bytes and browser screenshots remain outside tracked source. This batch is left uncommitted on the existing checkout.
