## Rendering fix

Super Mario 64 first reproduced repeated `glMapBufferRange` MAP_READ failures.
GLideN64 selected its native GLES3 pixel-buffer reader, while the pinned
Emscripten implementation rejects that read mode. The source recipe now selects
GLideN64's existing direct ReadPixels reader for Emscripten. Native factory
branches remain unchanged.

The regression compiles the actual original and patched ContextImpl factory to
LLVM IR against the pinned core headers, verifying the selected constructors.
The source stage reused the previous verified object cache, recompiled only
ContextImpl, then performed the full-Asyncify O0 link. A second link produced
byte-identical loader, WASM and v0.2.0 manifest. A fresh application of the recipe
to pinned source content matches all ten changed/generated staged source files.
This is an incremental build and relink proof, rather than a new clean rebuild.
The original green/blue press/release cartridge also passed with the new pair.

## Plugin-declared touch defaults

The next gameplay check exposed a missing default: the compact controller
has no analog sticks. Plugins can now declare:

```json
{ "player": { "web": { "defaultInputLayout": "standard" } } }
```

The optional enum accepts `compact` and `standard`. It is bounded at manifest,
API-client and browser boundaries. The descriptor field is additive in v1;
TS/Swift models and the surface snapshot are regenerated. It selects an existing
host layout and does not execute plugin-supplied layout code.

Defaults merge before saved core and game patches. Explicit layouts and key
bindings retain priority. Loading a default does not write browser storage, and
changing this metadata alone does not change preference identity. Legacy Dolphin
keeps its existing standard layout and special labels when the field is absent.
The bounded contract/preferences review found no material issues.

N64 v0.2.1 changes only package version and this preset declaration; its verified
loader/WASM pair is identical to v0.2.0. Both binary and metadata provenance are
retained in external source-stage receipts. Public binary distribution remains
pending the existing renderer-permission question.

## Remaining checks

Real-game movement/analog qualification remains pending: the long gameplay
attempts encountered zero-axis gestures, a keyboard-state deadline and a runtime
startup timeout under extreme host load. The native input watchdog/rearm rules
have not been weakened to force those tests to pass. An isolated component acceptance then passed with the real Svelte touch surface,
input session/preferences, and actual opaque sandbox bridge/engine: dragging the
stick produced native virtual-gamepad X `0.764706`, and release restored all axes
to zero. That test uses a synthetic 2D frame pump to avoid large-core startup; it
is UI/bridge evidence and does not qualify N64 guest movement. No production
watchdog behavior was changed. Frontend-loop counts in the receipt include paused/repeated frames
and are diagnostic values, not an emulation benchmark.

Synchronized saves, native Safari qualification, broader game coverage and
bounded performance optimization remain deferred. ROM-hack compatibility and
long-running gameplay are not inferred from these boot/menu results.
