# Component notice closure, 2026-11-07

The [machine report](./notice-closure-2026-11-07.json) adds final-runtime evidence
for Atari800, Potator and PCFX, inventories the actual November 6 package notice
materials, and preserves four complete incorporated-component banners. The 58
previous modern/legacy component scopes remain indexed individually. This is
bounded technical evidence, not a determination that every distribution condition
has been satisfied.

Atari800's Caprice32-derived `file_exists` contributes to the final
`retro_vfs_exists` fallback. The selected non-LTO objects match their archive
members. The final wrapper retains the `stat` call and permission/directory tests
from the incorporated utility, although optimization removes the utility's
standalone name. This is a structural source/instruction witness with its own
explicit limitation, rather than a complete inlining origin map.

The complete Caprice32 notice requires its copyright, conditions and disclaimer
in documentation or other redistribution materials. The November 6 standalone
player package and consolidated notice ZIP omit that complete text; the
corresponding-source archive retains it. The newly prepared
[atari800-caprice32.txt](./notices/atari800-caprice32.txt) supplies the exact
2,157-byte source banner for package, source-sidecar and flat release exports.

Potator's selected `m6502.o` retains `Reset6502` and `Int6502` in the final runtime.
The previous machine scan captured individual copyright lines, while the complete
banners also contain noncommercial distribution terms and a modification
notification request. The new [source banner](./notices/potator-m6502-source.txt),
[header banner](./notices/potator-m6502-header.txt) and
[table banner](./notices/potator-m6502-tables.txt) preserve all adjacent terms.
Their sizes are 1,151, 831 and 895 bytes. These banners do not separately demand a
binary documentation copy; carrying them is conservative, complete attribution.
Potator's broader Unlicense declaration does not resolve their narrower terms.
All four notice spans and complete source files match the pinned primary upstream
URLs identified in the report.

PCFX's `j_rev_dct` survives with a 740-byte final function body. Its recovered IJG
README, attribution and modification documentation were already published on
November 6 and remain unchanged. The SHA1 FPL material also remains unchanged.
For all ten custom builds, the non-LTO hash object contains SHA1-family functions
before linking, but its emitted linker CODE contains only the recorded SHA256
and DJB2 functions. Their object relocations reference no SHA1-family function.
This corrects a compiler-input-only scope assumption; source redistribution still
includes SHA1, and no notice removal is proposed.

Three serial postlink probes use the retained SDK tools with two Binaryen workers.
Every complete non-custom WASM section—including CODE, DATA, types, imports,
exports, tables and elements—matches each retained checkpoint and final runtime
byte-for-byte. Added debug names are diagnostic metadata, so the diagnostic files
are not claimed to be exact whole published artifacts. Later probes read the
original nameless inputs: Binaryen's pinned reader assigns each defined input
function its ordinal, allowing source names to be transferred through reordering
without influencing optimization. The initially failed propagated-name experiment
is excluded from successful evidence. No source build or runtime launch was used.

The report retains 40 positive component/build function witnesses across the three
probes. Header dependencies alone and names shared by multiple emitted object
owners are excluded. Eight static-data intervals additionally confirm retained
Atari NTSC presets and Altirra arrays. Missing function names do not establish that
inlined code or incorporated static data is absent.

The helper adds the four new banners only to Atari800 and Potator. The other eight
November 6 package notice sets remain byte-identical. The existing FPL/IJG files
are preserved, and package, corresponding-source and flat artifact export tests
cover the new materials. Publication and any new catalog references are recorded
separately; the previous publication receipt remains immutable.

Full third-party notice closure remains open. The final witnesses also confirm
xxHash, tracker, RAR, bcdec and GNU-licensed filters whose complete component
materials are absent from the standalone package notice sets. Several BSD banners
expressly address binary documentation/materials. The source/audit records retain
those texts, but a complete binary-material consolidation is still needed. The
other seven custom runtimes, unresolved header/inlining scopes and nested
components of the 50 upstream cores also need proportionate final-scope work.
Independent SDK archive reconstruction and the VitaQuake2/FBNeo byte mismatches are
tracked separately. The report enumerates these remaining gaps without promoting
source reconstruction into complete notice applicability.
