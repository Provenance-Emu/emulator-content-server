# Web playback

The same server that syncs a library can play a file in the browser. One account, one copy of each file, and the apps keep using the REST API. A VPN or a reverse proxy is another way to reach that origin. It is not a second library.

This waits until a registered folder can be scanned and a local file can be streamed. Do not vendor a core, and do not commit a ROM.

## Owned paths

- `apps/web` player page, after source content exists
- a same-origin route for cores the operator has placed in the data directory
- tests with generated bytes only

## Behavior

- The player lives on `/ui`, the same origin as the API. The bearer token and the LAN rule already decide who can read. No new CORS origin. The tray remains the only cross-origin caller.
- Cores are the libretro Emscripten builds (a `.js` loader and a `.wasm` core from the libretro buildbot). The operator downloads the cores they are allowed to run and puts them where the server can read them. The server then serves those files to a signed-in reader. The browser does not hotlink the buildbot.
- Play starts from a source file or an asset whose availability is `local`. The page fetches bytes with the content route, including ranges. `evicted` and `offline` are shown as names. The player does not open them, because opening an evicted file starts a provider download.
- Battery saves and save states already in the library load into the session. A save the player writes goes back through the upload route, so a phone and the apps see the same file. Keep-both still applies.
- Cloud, a VM, and a TLS reverse proxy use `token` access and `--public --tls-terminated`. The process keeps ignoring `X-Forwarded-For`. A proxy sitting on loopback must not become the owner. See [Container install](container-install.md).

## Acceptance

- A generated local file can be fetched by the page and passed to a core as bytes. The test commits neither a ROM nor a core.
- An evicted or offline file never starts the core.
- A save written by the page is the asset a device syncs.
- A session that arrives through a VPN or a TLS proxy uses its bearer token.

## Non-goals

Vendoring RetroArch or cores, netplay, sideload, JIT, a relay, and downloading an evicted file in the background.
