# CHD Disc Provider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Work task-by-task with focused TDD, task reviews, and a whole-branch review.

**Goal:** Add explicitly enabled CHD v5 DVD ISO and a tested CD CUE/BIN logical view without changing original stored bytes.

**Architecture:** Storage parses bounded metadata and delegates codecs to an operator-configured chdman. A versioned atomic artifact group preserves CD descriptor/binary identity. Existing entries and range routes consume those artifacts; no new HTTP operation is required.

**Tech Stack:** Node 22.22.2, TypeScript, existing virtual-provider ports, optional MAME chdman.

**Spec:** `docs/superpowers/specs/2026-10-19-chd-design.md`.

## Global Constraints

- Keep protocol/domain free of filesystem, SQLite, Fastify, and process implementations.
- Use generated bytes in tests; commit no CHD, ISO, CUE, BIN, ROM, BIOS, disc, or save fixture.
- Default startup stays ZIP-only with no native command probe. CHD requires an explicit absolute executable path and successful command-support probe.
- Support v5 standalone DVD and single-session, zero-gap, no-subcode CD modes proven by generated native round trips. Reject parent/delta, GD-ROM, older headers, unsupported modes/gaps, and nested CHD windows before extraction.
- Never use extractraw as a CD representation. CD files are fixed names `disc.cue` and `disc.bin`; DVD is `disc.iso`.
- Preflight total expanded bytes, ratio, entries, metadata bounds and arithmetic; enforce deadline/concurrency/output monitoring and exact-size acceptance with cleanup. Do not describe monitoring as an OS disk or memory sandbox.
- One logical feature PR, merge commit after required checks. Leave primary checkout and local main untouched; no publication.

## Review Focus

- Mixed data/audio CD track offsets and sector sizes must survive extraction without CHD padding becoming visible.
- A forged metadata chain must not cause cycles, unbounded allocation, or out-of-file reads.
- Concurrent CUE/BIN requests must observe one complete versioned group, never partial or mismatched files.
- Decoder failure, timeout, overrun, abort, and shutdown must join the process before deleting staging files.
- A missing/old tool must never produce an advertised CHD capability; valid chdman help can exit 1.

### Task 1: Provider, decoder, and artifact groups

**Files:** `packages/domain/src/index.ts`; new `packages/storage/src/{chd,chd-decoder,chd-cache}.ts`; `packages/storage/src/{virtual,virtual-cache,index}.ts`; focused tests in `packages/storage/test`.

**Interfaces:**
- Add `VirtualResolution` alternative `{ kind: 'bundle'; entry: VirtualEntry; bundleId: string }`.
- Add internal `VirtualArtifactBundle` with `version: string` and `files: { entryId: string; path: string; size: number; sha256: string }[]`.
- Add optional provider `materializeBundle(filePath: string, bundleId: string, destinationDirectory: string, quota: MaterializeQuota, signal?: AbortSignal): Promise<VirtualArtifactBundle>` and optional `close(): Promise<void>`.
- Registry dispatches the optional hook and closes providers. Existing ZIP range/expand paths retain their behavior.
- Export `createChdProvider(executable: string): Promise<VirtualContentProvider>` from storage; resolve/probe once, returning a validated provider or an actionable configuration error. Inject the process runner for portable unit tests.
- DVD entry ID `0` is `disc.iso`; CD ID `0` is canonical `disc.cue`, ID `1` is `disc.bin`. Bundle version is `chd-v1`.

- [ ] Write failing synthetic-header/metadata tests for magic/version/parent, DVD/CD identification, unsupported layouts, truncated/cyclic/out-of-file chains, unsafe arithmetic, quotas, exact CUE size and track index calculation. Run focused tests and observe intended RED.
- [ ] Implement bounded header/metadata parsing against the primary MAME declarations. Cap metadata at 128 records and 64 KiB total; reject duplicates/conflicting disc tags. Apply the existing materialization quotas to the complete artifact group before native execution.
- [ ] Write runner/cache tests for argument arrays, no shell, bounded logs, timeout/abort/overrun/nonzero/spawn failures, cleanup, single-flight, atomic winner publication, stale/invalid manifests and symlink outputs. Ordinary CI must use portable injected runners.
- [ ] Implement private random staging directories; at most one native decoder job and eight queued distinct groups per provider instance, bounded per-process memory/log buffers and one job deadline covering queue/decode/hash/publication. Await process exit on every cancellation path. Count all staged side files; validate regular fixed-name outputs, expected sizes and hashes before publishing the complete manifest. Cross-process writers use atomic winner validation rather than accepting partial groups.
- [ ] Key groups with outer SHA-256, provider/version and bundle ID. Return existing `VirtualEntryBytes` for the requested group file. Reject bundle resolution after another expansion and reject CHD inspection when a `VirtualWindow` is supplied; this first slice must not reset nested expansion budgets.
- [ ] Restore GREEN, run storage/domain tests plus existing ZIP regressions, self-review, commit, and write the task report with exact RED/GREEN evidence.

### Task 2: Server/CLI enablement and generated native acceptance

**Files:** `apps/server/src/{app,context}.ts`; `apps/cli/src/{main,service}.ts` and existing service specification/argument files as appropriate; `packages/protocol/src/capabilities.ts` only if needed to use the registry format list; server/CLI/storage tests; operator/workstream docs; optional focused CI workflow.

**Interfaces:** `OpenServerOptions.chdmanPath?: string`; `ecs serve --chdman <absolute-path>` and `ECS_CHDMAN_PATH`; preserve optional path in per-user service registration without credentials. Server registry uses the Task 1 factory only when explicitly configured and closes it on shutdown.

- [ ] Write failing enablement/probe tests: default `[zip]`, configured compatible tool adds `chd`, missing/incompatible tool fails startup clearly, valid help exit 1 is accepted, no probe before configuration. Verify service round-trip and exposure-policy behavior.
- [ ] Register the provider and preserve existing authorization before entry lookup/materialization. Retain GET/HEAD/ranges, stable ETags, offline locations and source containment behavior.
- [ ] Generate a DVD and mixed-track CD from deterministic noisy bytes using the installed configured chdman. Prove whole bytes and nonaligned ranges, track modes/INDEX offsets, CUE references, both CD entry IDs, cache reuse and rejection of excluded layouts. Only enable each CD mode after its generated round trip passes; do not silently reduce the advertised scope.
- [ ] Native integration can skip locally when no path is configured; a dedicated explicitly enabled integration job must fail if its configured decoder is missing. Use a pinned/integrity-checked tool source, keep ordinary Linux/macOS/Windows tests independent of native availability, and document actual tested platforms.
- [ ] Document configuration, exact supported layouts, optional dependency, cache and native isolation limits. Do not claim RVZ/CISO, nested CHD, arbitrary multisession/subchannels or browser-disc core acceptance.
