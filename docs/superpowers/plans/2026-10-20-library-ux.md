**Goal:** Deliver the approved Plex-style library and settings experience in the browser, then share it with the desktop application and its native folder selector.

**Architecture:** Add a bounded read projection over existing managed items/assets and scanned sources. Shared Svelte components consume that API through injected server/session/platform adapters. The native shell owns trusted local-service verification and dialogs; storage and authorization remain in the server.

**Tech Stack:** Node 22.22.2, pnpm 10.30.1, TypeScript, node:sqlite, Fastify, Svelte 5, Vite, generated TypeScript/Swift clients, Tauri 2/Rust. Add Playwright only as a browser-test dev dependency during execution.

**Spec:** `docs/superpowers/specs/2026-10-20-library-ux-design.md`, approved by the user on 2026-10-20. This plan is written for review before execution.

## Global Constraints

- “Both browser and desktop matter; browser comes first.”
- “Use 50 entries by default and a server maximum of 100.”
- “The tabs are Games, Saves, Media, and System files.”
- “The single final action is Create library.”
- “There is no intermediate Use this folder followed by another Add form.”
- “Merely opening a screen or adding one folder must not scan other registered folders.”
- “Never default to the first system in the server's list.”
- “Do not silently merge records by title, copy files, rewrite saves, or convert sources to managed assets.”
- “Keep HTTP composition in apps/server, queries and persistence in packages/database, DTOs/cursors in packages/protocol, and UI data access through @ecs/client.”
- “Keep native code and dependencies in apps/tray; apps/web must not import Tauri.”
- “Never load remote server HTML into a webview with privileged commands.”
- “Leave the primary checkout and local main untouched.”
- “Write failing behavior tests before implementation.” Use generated bytes only; never commit copyrighted fixtures, bootstrap tokens, bearer tokens, passwords, or raw authorization logs.
- Preserve existing `/sources` semantics and player isolation/CSP. Add new numbered migrations; regenerate contracts with `pnpm generate`, `pnpm update-surface`, and validate drift.
- Use fresh implementer and task reviewer agents, explicit model routing, and no nested agent dispatch from workers. Integration/query/UI tasks and task reviews use `gpt-6.1-sol` (sonnet role); mechanical fixes use `gpt-6-luna` (haiku role). Whole-PR final review uses `gpt-6-astra` for synthesis. Never silently inherit the most expensive model across a fleet.

## Review Focus

- Lost create/commit responses must not create duplicate libraries, items, roots, or assets; pin reconciliation in Tasks 4 and 5.
- Server switches, sign-out and revoked access must discard stale private results and never send another server's token; pin deferred-response/origin tests in Tasks 2, 3 and 6.
- Literal wildcard and non-ASCII names, tied names, deleted cursor anchors, and restricted rows before a page boundary must remain searchable/pageable without leaks; pin in Tasks 1 and 2.
- Offline roots and settings visits must not turn a bounded page read into a full scan/probe or source-change storm; pin probe-count tests in Task 2 and scan-call tests in Task 4.
- Native dialogs must not treat a loopback-looking remote profile or a running service label as proof of local endpoint ownership; pin service/PID/listener/window tests in Task 7.

Shared types are defined by their owning task and consumed verbatim later:

```ts
// Task 2: exported by @ecs/client (wire envelope supports the existing generator).
type LibraryScope = { libraryId: string } | { unassigned: true };
type BrowseCategory = 'games' | 'saves' | 'media' | 'system_files';
type BrowseSort = 'name_asc' | 'name_desc';
type LibraryBrowseQuery = LibraryScope & {
  category: BrowseCategory; rootId?: string; systemId?: string;
  search?: string; sort?: BrowseSort; cursor?: string; limit?: number;
};
// Generated model: entityType plus exactly its matching payload at runtime.
interface LibraryBrowseEntry {
  entityType: string; id: string; name: string;
  libraryId: string | null; systemId: string | null;
  item?: Item; asset?: Asset; source?: SourceFile; parentItem?: Item;
  previewAsset?: Asset; // item entries only; an authorized existing artwork asset
}
interface LibraryBrowsePage { items: LibraryBrowseEntry[]; nextCursor: string | null }

// Task 3: web-owned injected application context.
interface SessionStore {
  load(): StoredSession | null; save(value: StoredSession): void; clear(): void;
}
interface ServerContext {
  key: string; origin: string; label: string; client: ContentClient;
  sessions: SessionStore; openPlayer(relativeHref: string): void;
}
// Task 4: web-owned native capability, supplied only by desktop Task 7.
type FolderPurpose = 'library-folder' | 'upload-storage';
interface FolderSelection {
  path: string; suggestedName: string; origin: string; contextKey: string;
  verificationId?: string;
}
interface FolderSelectionAdapter {
  choose(request: { contextKey: string; purpose: FolderPurpose }): Promise<FolderSelection | null>;
  validate(selection: FolderSelection): Promise<boolean>;
}
```

`StoredSession` remains the existing token/expiry shape. Browser composition supplies no native folder adapter: the shared chooser directly renders server-directory browsing with the actual final submit action. A native adapter returns `null` on cancellation; it does not fall through into a second chooser. All selection submissions check origin/context again.
