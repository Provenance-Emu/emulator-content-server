**Goal:** Deliver independently installable workflow/translator/tool plugins and durable library-cleanup batches, then attach API-key backends and MCP to the same evidence, operation and proposal contracts.

**Architecture:** Executable plugins and backend SDKs run in the separate plugin host. The content API owns authorized source facts, run/proposal records, staged artwork, exact batch approvals and conditional undo. A deterministic cleanup workflow is the first end-to-end feature; model translators and MCP adapters are additional producers of observations and proposals, never alternative mutation paths.

**Tech Stack:** Node 22.22.2, pnpm 10.30.1, TypeScript/ESM, `node:test`, Fastify, `node:sqlite`, JSON Schema 2020-12, Svelte 5 and focused Playwright checks. Use Ajv's 2020-12 validator, AI SDK behind translator modules, and the official MCP TypeScript server/client packages; SDK versions are resolved and pinned exactly when their tasks execute.

## Global Constraints

- **PRE-RELEASE: NO EXTERNAL PRODUCTION; NOT SHIPPING.** No release hardening or publication is part of this plan.
- `packages/plugins` has no internal dependencies. `apps/plugins` may depend on `@ecs/plugins`, `@ecs/client`, `@ecs/protocol`, and `@ecs/signing`; it may not import the content server, catalog or blob store.
- Installed modules and backend SDKs never execute in the HTTP process or browser. `apps/web`/`apps/tray` use `@ecs/client` exclusively for server access.
- Preserve `ecs.plugin/1` and existing `scan`/`match` job/API semantics. Add `ecs.plugin/2`; use separate additive workflow-run routes, not new values in existing job enums.
- Initial cleanup execution, plugin installation, connection management, approval/application and undo are owner-only. MCP and host service identities have narrower grants and are not owner sessions.
- Initial scope: indexed server-folder games; metadata/system selections and front artwork only. No source-file moves, renames, deletions or patching; suppress automatic organization on cleanup writes.
- No model can assert verified source evidence, grant itself tools, change permissions, approve proposals or expand cloud data sharing.
- Credentials never appear in manifests, the content database, logs, errors, model context, generated diagnostics or browser persistence. Public connection reads expose references and safe summaries only.
- Preserve exact region/edition conflicts; distinguish provider failure from no match and unsupported identification from wrong identity.
- Retain pending-review work until explicit deletion. Completed/rejected staging and undo retention is 30 days; selected artwork is retained independently.
- Append numbered migrations; never rewrite shipped migrations. Current server migration maximum is 20; re-read at execution and allocate the next unused number rather than assuming 21 remains free.
- Regenerate with `pnpm generate`; update `pnpm update-surface` for intentional additive HTTP changes; `pnpm check-drift` must pass. Never hand-edit generated TS/Swift models.
- Use generated bytes/facts and fake services for tests. No real keys, operator catalogs or game files; no paid live API calls are required for acceptance.
- Keep this batch on the existing authorized branch/worktree. Changes from the concurrent browser-player task are outside scope. Commit checkpoints below mean focused commits only when authorized; no per-task PRs, pushes or releases.

## Review Focus

1. A worker loses its lease after a backend accepted a paid call: refuse stale publication and reconcile saved handles without automatically buying another call (Tasks 4–5, 11).
2. Two owner sessions review different proposals for the same source: approval binds exact bytes/versions, and stale application or undo preserves the later selection (Tasks 7–9).
3. An image disappears after its matching preview expires, or review waits through restart: materialized metadata/artwork still previews and applies without the original request cache (Task 7).
4. An owner activates/disables a community update during a run, or a backend key is revoked: pinned code/configuration and revoked authority govern every new step (Tasks 2, 5, 10–11).
5. A model/MCP result names another library, supplies an invented checksum or embeds tool instructions: reject scope escalation and retain observations as unverified data (Tasks 6–7, 12–13).

`@ecs/protocol` owns shared library-facing wire types and limits. `@ecs/domain` owns repository/service records, importing only protocol types. `@ecs/plugins/workflows` owns executable-plugin ABI and its capability schemas, without importing protocol/domain. Host and server adapters convert and validate at that boundary; do not violate dependency direction to share one internal type alias.

## Planning decisions used by all tasks

**Initial limits:** 50 source work items per repository page; 20 findings/proposals per UI page, maximum 100 per API page; two source workers per host; one active step per source; 64 queued operations; 64 KiB manifest, 256 KiB schema, 1 MiB IPC/publication envelope, 64 KiB checkpoint, maximum JSON depth 32; 10 proposals and 100 candidate references per source. Bound artifacts to existing PNG/JPEG/WebP and 2 MiB each, maximum 16,384 pixels on either dimension and 40 million pixels total. Default staging quotas: 64 MiB per run, 512 MiB per library and 1 GiB per server for unselected workflow staging. Capacity errors preserve reviewable work. All configurable increases remain owner choices; malicious input cannot set these limits.

**Leases:** 60-second leases, renew every 20 seconds, long-poll at most 20 seconds. Use a fake clock in tests. Pin host installation identity, plugin/schema/configuration digests and selected model ID. Lost host state is `recovery-required`; never silently transfer to another host. Server run states: `queued`, `running`, `interrupted`, `completed`, `cancelled`, `failed`, `recovery-required`. Review/application state is separate from inspection completion.

**Common ABI names:** `JsonValue`, `WorkflowPluginV2`, `TranslatorPluginV2`, `ToolPluginV2`, `CapabilityDescription`, `OperationRequest`, `OperationResult`, `OperationContext`, `WorkflowSnapshot`, `WorkflowPlan`, `CleanupObservation` and `CleanupProposalDraft` are exported by `@ecs/plugins/workflows`. Workflow method: `advance(snapshot: WorkflowSnapshot): Promise<WorkflowPlan>`. Translator methods: `describe(context): Promise<CapabilityDescription[]>`, `start(request, context): Promise<OperationResult>`, optional `poll(request, handle, context)` and `cancel(request, handle, context)`. Tools implement `describe`/`start`, plus optional async methods when advertised. Workflow snapshots and plans are JSON-only; secrets, functions, file paths and service credentials are not ABI payloads.

Task 1 also owns the support types referenced by those signatures: `WorkflowManifestV2`, `SchemaDocument`, `LoadedWorkflowPlugin`, `OperationError`, `Usage`, `TextGenerationInput`, `StructuredGenerationOutput`, `ImageInspectionInput` and `WorkflowPackage`. `TextGenerationInput` carries bounded prompt/messages, optional response schema and output ceiling; `StructuredGenerationOutput` carries the generated `JsonValue`. `ImageInspectionInput` adds explicitly authorized artifact references. `Usage` uses integer token counts and nullable estimated/reported integer micro-currency amounts with a currency code; wire/Swift models do not silently round fractional prices to integer currency units. Cleanup parses generic structured output into its own observation schema; translators do not import cleanup rules.

**Repository names:** expose `catalog.workflowRuns`, `catalog.workflowProposals` and `catalog.workflowIdentities`; implement each as its own repository constructed with the catalog's SQLite connection. Cross-source transactions are unnecessary; source changes plus application receipts share one transaction.

**Public routes:** add groups only in the task implementing their handlers and register their operation metadata then. `/api/v1/workflow-runs` covers creation/listing; `/{runId}` covers inspection; child resources are `findings`, `proposals`, `evidence`, `artifacts`, `decisions`, `approvals`, `applications`, `cancel` and `resume`. `/api/v1/workflow-applications/{applicationId}/undo` restores a committed source group conditionally. `/api/v1/workflow-hosts` provisions/revokes hosts; `/enroll`, `/claim`, `/heartbeat`, `/publish` and `/control` under `/api/v1/workflow-workers` are narrow host operations. Owner management uses `/api/v1/workflow-hosts/{hostId}/plugins` and `/connections` plus named child actions. `/api/v1/workflow-access-tokens` issues/revokes MCP grants. All request/result schemas and ContentClient methods are added with their handler task.

**Generator compatibility:** keep public cleanup/resource payloads as concrete object schemas. Plugin configuration/schema and host-private generic envelopes use explicitly named, byte-bounded JSON strings (`configurationJson`, `schemaJson`, `payloadJson`) decoded/validated by adapters; do not rely on today's Swift generator to encode nested arbitrary JSON dictionaries. No secrets are persisted in publication envelopes. This is a transport detail; UI presents ordinary fields and descriptions.

**Verification conventions:** tests use `node:test`/`assert`, not Vitest. For each task, add the regression first, compile the affected projects with `pnpm exec tsc -b <projects>`, and run the named `node --test <compiled-tests>` command. Before implementation, an absent export can fail compilation; record that expected failure, then rerun to PASS after implementation. Each assertion sketch below assumes the task's generated fixture; implement the fixture with the listed public interfaces rather than treating the sketch as another production API. Every task has a focused commit checkpoint when commits are authorized. No runtime checks are run while merely writing this plan. Before execution, inspect the current branch/status and baseline affected checks; preserve concurrent changes and report unrelated failures rather than reverting them.
