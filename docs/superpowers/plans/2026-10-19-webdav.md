# Authenticated WebDAV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship opt-in, read-only WebDAV with bearer access and revocable Digest
app credentials that work with Finder's authentication and browsing sequence.

**Architecture:** A pure `@ecs/webdav` package processes virtual paths and DAV
properties through an injected namespace. The server supplies an ACL-filtered
namespace and streams files through shared REST content helpers. Authentication
algorithms stay in auth; credential persistence stays in the catalog.

**Tech Stack:** Node 22.22.2, pnpm 10.30.1, TypeScript, Fastify, SQLite,
namespace-aware XML parsing, existing Node test runner and generated clients.

**Spec:** `docs/superpowers/specs/2026-10-19-webdav-design.md`

## Global Constraints

- Work only on `codex/webdav-compatibility` in its existing worktree. Leave local
  `main` untouched. Commit and push, create one PR, fix CI, merge when green.
- Read-only DAV; `/api/v1` remains the write/upload API. WebDAV is off by default.
- DAV requires credentials even on loopback/LAN and for OPTIONS/PROPFIND.
- Fixed realm: `Emulator Content Server WebDAV`; `qop=auth`; SHA-256 and MD5.
- Random 32-byte app passwords, shown once; store only HA1 verifiers.
- Credentials: trimmed label 1–80 characters; lifetime 60 seconds to 365 days,
  default 90 days; at most 32 active credentials per account.
- Credential management requires a real account-session bearer token.
- Nonces: five-minute lifetime; replay window 64 counts; cache 10,000 contexts;
  full live cache returns 503 rather than evicting replay protection.
- XML: 32 KiB, nesting 16, properties 128; reject DTD/entity declarations.
- PROPFIND Depth 0/1 only; infinity/missing Depth returns finite-depth error.
- At most 10,000 children per collection response; overflow returns 507.
- New migration 8; do not edit migrations 1–7. Open an upgraded catalog twice.
- New additive credential endpoints, regenerated clients/surface, feature flag.
- No real content fixtures, credential logging, UI/tray changes, playback, locks,
  arbitrary persistent properties, or archive expansion.

## Review Focus

- Finder's parallel requests may arrive out of nonce-count order; distinct counts
  inside the 64-count window succeed, repeated/old counts fail (Task 1).
- Unicode names may use decomposed forms; canonical DAV lookup accepts equivalent
  normalized filenames while Digest verifies the exact received URI (Tasks 1/3).
- A per-item grant without library membership must remain usable without leaking
  sibling items or scanned roots (Task 3).
- A source is unplugged or becomes a placeholder after listing; GET rechecks
  presence and returns the existing offline/evicted response (Task 3).
- Reverse proxies and tray-origin preflight headers must not accidentally enable
  local admission or unauthenticated DAV OPTIONS (Tasks 2/3).

- Modify `packages/auth/src/index.ts`.

**Interfaces:**

  `challenges(stale?: boolean): string[]` and
  `verify(input: { header: string; method: string; uri: string },
  lookup: (username: string) => DigestVerifier | null): DigestResult`.
- `DigestResult` is `{ kind: 'ok'; credentialId: string }` or
  `{ kind: 'invalid' | 'stale' | 'full' }`.

  independently calculated client response. Assert successful authentication,
  exact method/URI binding, duplicate/missing parameters, malformed quoting,

- [x] Run `pnpm build && node --test packages/auth/dist/test/digest.test.js`;
  observe missing-export failures before implementation.
- [x] Implement parsing, fixed-realm challenges, HMAC-authenticated process-local
  nonces and opaque values. Limit Authorization to 8 KiB and cnonce to 128 bytes.
  Accept omitted algorithm as MD5; accept only positive eight-hex-digit nc.
  Unknown/expired/revoked credentials are represented by null from lookup.
- [x] Add replay/clock tests: counts 2 then 1 succeed; repeated 1 fails; 65 then 1
  fails; a tampered nonce fails; an expired otherwise valid response is stale;
  an expired response with a wrong password is invalid; a new process key rejects

  state still works; advance past nonce expiry and assert capacity is reclaimed.
- [x] Implement replay updates only after a valid response; use a BigInt bitset
  for the 64-count window and synchronous check/update to prevent parallel replay.

### Task 3: DAV protocol, ACL namespace, and shared streaming

**Files:**

  `src/paths.ts`, `src/properties.ts`, `src/handler.ts`, `test/webdav.test.ts`.
- Create `apps/server/src/webdav.ts`, `webdav-namespace.ts`, `content.ts`.
- Create `apps/server/test/webdav.test.ts`.
- Modify `apps/server/src/app.ts`, `routes.ts`, `http.ts` as needed for focused
  extraction; retain existing REST behavior.
- Modify `packages/protocol/src/capabilities.ts` and its tests, workspace TS
  references, server manifest/references, boundary declarations, pnpm lockfile.

**Interfaces:**
- `DavResource { segments: string[]; displayName: string;
  kind: 'collection'|'asset'|'source'; id?: string; size?: number; etag?: string;
  createdAt?: string; modifiedAt?: string }`.
- `DavNamespace { resolve(segments: string[]): Promise<DavResource|null>;
  children(resource: DavResource): Promise<DavResource[]> }`.
- `handleDav(input: {method:string; url:string; depth?:string; body?:string},
  namespace: DavNamespace): Promise<DavResponse>`; response is
  `{status:number; headers:Record<string,string>; body?:string; file?:DavResource}`.
  A GET/HEAD file response carries `file` for the server to stream; protocol code
  has no filesystem/catalog imports. Errors use domain errors or DAV XML errors.
- `createDavNamespace(context, actor): DavNamespace` and
  `registerWebDav(app, context): void` implement server integration.
- Extract existing `sendSourceContent`/`sendContent`/range helpers into
  `content.ts` with explicit `assetId`/`sourceId` arguments rather than mutating
  request params. REST and DAV call the same content senders.

- [x] Write package tests for Depth 0/1/infinity/missing/invalid; empty/allprop,
  propname, explicit namespaced properties, 200/404 propstat; collection hrefs,
  XML escaping, Unicode names, and read-only method rejection. Assert 32 KiB,
  nesting 16, property 128 and child 10,000 limits; hostile DTD/entity XML fails.
- [x] Add package/build/boundary declarations, run focused tests red, then
  implement pure DAV processing with a maintained namespace-aware parser. Check
  primary package documentation/current registry release before selecting it.
  Never enable entity resolution. Encode hrefs per segment; use normalized
  filenames only for virtual lookup, never before Digest URI verification.
- [x] Write raw-path tests for literal/encoded dot segments, encoded separators,

- [x] Implement server namespace: `/dav/` lists libraries and sources;
  `/dav/libraries/<libraryId>/<itemId>/<assetId>--<safeDisplayName>` identifies an
  asset; `/dav/sources/<rootId>/<validatedRelativePath>` identifies a scanned
  source. Use canonical ID directories and sanitized filename suffixes, with
  displayname properties for titles. Require canonical identity matches on lookup.
- [x] Add ACL tests for owner/member/read scope, nonmember item grants,
  library/item-scoped guests, and restricted assets even with guest

  return 404 for invisible resources. Include per-item grant revocation and
  membership removal between requests. Iterate all catalog pages within limits.
- [x] Add source tests for nested paths, Unicode normalization, file/directory
  name collisions, offline/evicted transitions without hydration, guests with

- [x] Add global-hook integration tests: no local DAV admission, no tray-origin
