# First disc provider: CHD v5 with an optional operator decoder

## Binding implementation profile

The companion implementation plan fixes the proposed interfaces and limits: `bundle` resolution plus optional `materializeBundle`/`close` ports, storage factory `createChdProvider(executable)`, version `chd-v1`, at most 128 metadata records and 64 KiB metadata, one active decoder and eight queued distinct groups per provider instance. Preflight and exact-size acceptance apply to the complete group. Byte-overrun monitoring and private staging are not an OS disk/memory sandbox. Unsupported layouts and nested CHDs are rejected explicitly; other disc formats are not implied by CHD support.

Design based on read-only investigation, 2026-10-19. No product implementation or fixture generation has been performed. Repository AGENTS.md and the supplied instructions were read; RTK.md is absent from this checkout and the checked parent/source locations.

## Recommendation and explicit scope

Use CHD v5 as the first disc provider, with an explicitly configured operator-owned `chdman` executable. `/opt/homebrew/bin/chdman` exists here; its help identifies version 0.289 and supports `extractcd`, `extractdvd`, `createcd`, `createdvd`, and `dumpmeta`. Do not bake that machine path into defaults. No user choice is needed: this is a sound first-format default within the authorized disc-container work.

A correct first change should support standalone DVD CHDs as `disc.iso`, plus a precisely bounded CD subset as `disc.cue` and `disc.bin`. For the smallest CD slice with exact pre-extraction size metadata, accept modern CHT2, one session, no subchannels, zero pregap/postgap, and only individually tested MODE1, MODE1_RAW, MODE2_RAW, and AUDIO tracks. Include multiple tracks and mixed data/audio. Reject any layout outside that subset, including GD-ROM, multisession, nonzero gaps, legacy metadata, and unsupported track modes, with a clear unsupported-entry response. This is intentionally narrower than every CD CHD. Expanding gap support later requires generated gap/index fixtures and proven byte accounting, not just accepting the metadata strings.

Do not advertise support for RVZ, WIA, GCZ, CISO, delta/parent CHDs, HD/laserdisc/raw CHDs, or older CHD header versions. The accepted scope includes that bounded CD slice; do not silently reduce it to DVD-only or expose `disc.raw` as a playable CD representation.

MAME documents separate CD and DVD extraction commands; the installed help confirms CD supports separate descriptor/binary output and DVD supports one output file. Delta input requires a parent, which this provider will not supply. [MAME chdman documentation](https://docs.mamedev.org/tools/chdman.html).

CHD is a better first step than RVZ because an installed supported tool can handle the codecs. RVZ requires partition reconstruction, hash exceptions, packing/PRNG behavior, and multiple compression methods; a new independent reader is appreciably more work. [Dolphin WIA/RVZ format specification](https://github.com/dolphin-emu/dolphin/blob/master/docs/WiaAndRvz.md). Dolphin CISO is smaller in scope but discards unused information, so reconstruction would need an explicitly qualified logical-view promise. The name also needs careful format identification rather than trusting an extension. [Dolphin supported formats](https://dolphin-emu.org/docs/faq/#what-dump-formats-are-supported-by-dolphin). No Dolphin reader source was inspected or imported.

## Existing seams and necessary changes

`VirtualContentProvider` in `packages/domain/src/index.ts` exposes inspect, resolve, and single-file materialize. `packages/storage/src/virtual.ts` registers ZIP and provides quotas; `virtual-cache.ts` caches each entry separately. `apps/server/src/app.ts` currently constructs only ZipProvider. The entries route already returns `items` with IDs/paths/sizes and supports ranged GET/HEAD for content. These are suitable public endpoints for disc artifacts.

Add `packages/storage/src/chd.ts` for bounded header/metadata inspection and supported-layout validation, and a small `native-decoder.ts` for process lifecycle/budgets. Keep all filesystem/process code in storage. Export through storage index. Do not add process or filesystem dependencies to domain/protocol. Add an optional group hook to the domain port, implemented only by CHD; ordinary ZIP materialize stays usable unchanged.

A concrete minimal shape is `VirtualResolution` gaining an internal `bundle` alternative with `bundleId`, selected `entryId`, and logical path. Provider gains `materializeBundle(filePath, bundleId, destinationDirectory, quota, signal?)`, returning a versioned manifest of fixed-name files, each with entry ID, size, and SHA-256. Registry dispatches this method. Storage owns the directory and atomic publication. Pass cancellation through the open/cache call or at least use a job-scoped signal; do not hide subprocess lifetime inside an untracked detached task.

## Logical bytes and entry contract

DVD: ID `0`, `disc.iso`, extracted 2048-byte sector data, exact length from validated DVD logical size. Verify the DVD marker, unit size and alignment; a raw CHD with unit size 2048 is not sufficient identification. No assertion that the image contains ISO9660 is necessary; the name denotes a conventional sector image.

CD: ID `0`, `disc.cue`, and ID `1`, `disc.bin`. Use one concatenated BIN for the entire disc and one generated canonical CUE descriptor. Preserve track numbers, per-track sector mode, and track-relative INDEX 01 offsets. Every accepted mode has an explicit byte-size mapping; for the zero-gap subset, BIN size is the sum of accepted frame counts times mode sector bytes. Do not include CHD internal track padding in that size. A CUE consumer mounts both artifacts with precisely those relative names. Audio remains audio; never relabel an audio/mixed-mode image as ISO. Omit CRC when unavailable; CHD SHA-1 is not a track CRC.

CHD's header contains logical-byte, hunk, unit, metadata, and parent fields; v5 is 124 bytes and a nonzero parent SHA identifies parent dependence. [MAME CHD format declaration](https://github.com/mamedev/mame/blob/master/src/lib/util/chd.h). CD units include sector/subcode storage and padded tracks; track modes have different data sizes and audio semantics. Thus raw CHD expansion is not a substitute for CD extraction. [MAME CD layout declarations](https://github.com/mamedev/mame/blob/master/src/lib/util/cdrom.h). CHT2 declares track/type/subtype/frame/gap fields. [MAME metadata definitions](https://github.com/mamedev/mame/blob/master/src/lib/util/chd.cpp).

Listing must stay cheap and run no decoder: read the fixed header plus a bounded metadata chain, reject cycles/out-of-window offsets and conflicting/missing disc-kind tags, and construct the canonical CUE deterministically from the accepted layout. Its encoded UTF-8 byte length gives the exact listed CUE size. After extraction, validate the tool-produced descriptor against the accepted layout and canonicalize to the same deterministic CUE. Compare extracted BIN/ISO size against precomputed expectations before publication. A mismatch is an error, not an updated promise. Do not parse human-facing `chdman info` output as an API.

Use `method: chd-cue-bin` / `chd-dvd` (or equivalent documented values); `compressedSize` can be the complete container size because there is no meaningful disjoint compressed allocation per artifact. Document that it is shared source size and never sum it as physical storage. These fixed paths plus the CUE preserve semantics without an OpenAPI change. If an explicit disc/track manifest is desired later, add optional fields to openapi.yaml and regenerate TS/Swift/surface intentionally.

## One extraction, one immutable artifact group

Key the cache by outer container SHA-256, nested-entry identity if present, provider ID, and representation version (`chd-v1`). The current cache key lacks a representation version; do not reuse its unversioned output for a differently normalized CUE. One in-flight job per group prevents duplicate CUE/BIN extraction. Create a private random sibling directory, decode into fixed names, validate/hashes all files, write the manifest last, then atomically rename the directory to the final group. A group is readable only after this complete manifest is published. Ranges of either artifact then use FileContentReader/sendRange.

A second requester joins the first job. Cancel the native job only when no waiter remains (or on shutdown/deadline); disconnecting one waiter must not break another download. A process-local singleflight map does not coordinate multiple server processes: use an exclusive lock/atomic winner protocol or document that this data directory has a single writer. Invalid/incomplete cache directories are never accepted on stat alone. Include expected sizes and representation version in validation. Failure, deadline, abort, spawn failure, nonzero exit, or validation failure removes the entire staging directory, including side outputs. Startup can clean abandoned partial groups.

For this first slice, decline CHDs embedded as non-whole-file windows before spawning; do not accidentally decode an outer ZIP as a CHD. Nested support may later copy the bounded window into a quota-accounted immutable staging input. Existing explicit ZIP expansion may produce a whole CHD cache file, but its total expansion budget must be carried across the CHD hop before enabling that path. The current generic loop resets provider budgets per hop; do not claim aggregate nested quota coverage without fixing that accounting.

## Decoder containment and budgets

1. Configure an absolute executable path through OpenServerOptions and a CLI flag/environment setting; resolve it once. Probe command support once at startup only when explicitly configured. Cache the result. No subprocess on default `openServer()` or on every request/test. Default remains ZIP-only. Add CHD capability only for enabled and successfully probed decoder features. An absent/old/broken configured tool yields an actionable doctor/startup status, never a false capability.
2. Spawn with `shell: false`, an argument array, fixed generated output paths, private cwd, no inherited input, and bounded stdout/stderr. Supply no force/parent switches. Only absolute immutable blob input paths from storage; neither client paths nor CUE strings become command arguments. Do not return decoder stderr or host paths to callers. Inspect only regular output files and reject symlinks/unexpected files before publication.
3. Run `extractdvd -i INPUT -o PRIVATE/disc.iso`, or `extractcd -i INPUT -o PRIVATE/tool.cue -ob PRIVATE/disc.bin`. No split-bin mode in this slice. The CUE must reference only the known BIN; never follow a decoder-emitted arbitrary filename. Copy/normalize only verified artifacts to canonical names.
4. Before spawn enforce safe-integer arithmetic, bounded metadata records/bytes, maxEntries (including descriptor), parent absence, supported layout, maxExpandedBytes for the entire group, and ratio against container file size. Conservative additional bounds can include CHD logical bytes and hunk count. Zero-filled generated inputs can legitimately exceed the default ratio; tests must either use deterministic noisy bytes or explicitly choose a test quota.
5. Use one monotonic deadline covering inspect/preflight, queue wait, subprocess, hashing, and publication; do not restart a full timeout for each stage. Bound active decoders and queue length; reserve the declared group bytes against a shared in-flight storage budget. On timeout/abort terminate the process, escalate kill after a short grace period, await exit/stream closure, and only then remove its directory. On shutdown cancel and join jobs.
6. During extraction monitor actual aggregate staged bytes and stderr/stdout; kill on overrun, then verify exact lengths after successful exit. Account descriptor and auxiliary files, not only BIN. Release reservations in finally, including spawn errors. A fixed global cache capacity/eviction policy is separate from per-materialization limits and must not be described as solved by maxExpandedBytes.

Important limit: a direct chdman process writing files is not an OS sandbox. Polling output size cannot provide a strict disk-byte ceiling (there can be overshoot between checks), nor prevent a compromised native decoder from accessing host files. Describe this honestly. For a hard filesystem/memory boundary, use a constrained worker runner with an OS-enforced storage quota and memory limit, or a separately validated streaming decoder whose writes the parent strictly bounds. Node timers alone do not supply these guarantees. Cross-platform native sandbox parity is a material additional implementation task, especially Windows; do not quietly equate private cwd with containment. The initial operator-provided-tool mode can truthfully promise preflight limits, deadline/concurrency limits, overrun detection, exact-size acceptance, and cleanup; hard native isolation remains an explicit deployment limitation unless that runner is implemented.

## TDD and verification plan

All fixtures are synthesized at runtime in temporary directories. Do not commit .chd/.iso/.bin/.cue fixture data or touch real library content.

- Unit tests first: fake headers/metadata for magic/version/parent, DVD/CD discrimination, unsupported modes/gaps/subcode/session, truncation, integer overflow, cycles, offset bounds, excessive metadata/frames, ratio/size/entry quotas. No native binary required.
- Native adapter tests with an injected runner/fake executable: exact argument arrays and cwd, huge output, stderr cap, spawn/nonzero failures, timeouts, abort, kill escalation, concurrent waiters, shutdown, symlink/unexpected files, and full staging cleanup. Use a portable process-runner injection; Windows cannot execute a Unix shebang fixture as an .exe.
- Cache tests first: two simultaneous entry opens launch one group, CUE and BIN become available atomically, range bytes match, cache reuse launches nothing, failed extraction never publishes a manifest, representation-version keys differ.
- Real opt-in integration: synthesize deterministic DVD sector bytes and create with `chdman createdvd`; extract and compare whole SHA-256 plus nonaligned ranges. Synthesize a three-track CUE/BIN (data + audio + data) and create with `createcd`; compare data/audio bytes, track modes, INDEX offsets, descriptor references, BIN size, and requests for both IDs. Add one fixture per accepted mode and explicit rejection fixtures for every excluded layout. These tests decide which CD modes are actually enabled.
- Server tests: default capabilities stay `[zip]`; enabled+available adds `chd`; failed probe does not. Existing ACL/guest visibility applies to entries. Test GET, HEAD, 206 ranges, suffix ranges, 416, stable ETags, and no native process before authorization. HEAD currently opens/materializes an entry: preserve or deliberately optimize this and test the choice.
- Browser integration consumes the API through @ecs/client, mounts CUE and BIN into the same virtual directory, opens CUE as entrypoint, and checks both are loaded before starting a supported core. CHD decoding support alone is not proof of browser playback or core compatibility. Keep core assets external to git. This report does not claim those browser changes are implemented.

Commands after implementation: `pnpm build`, `node --test packages/storage/dist/test/chd.test.js packages/storage/dist/test/chd-integration.test.js`, relevant server/browser test files, `pnpm verify`, and `swift test --package-path clients/swift` on macOS. If optional public fields change, run `pnpm generate`, intentional `pnpm update-surface`, and `pnpm check-drift` before verification.

Existing CI already runs pnpm verify on Linux/macOS/Windows and Swift on macOS. Keep the ordinary matrix independent of chdman. Add a separate integration matrix with a pinned and integrity-checked compatible chdman supplied through ECS_CHDMAN_PATH: Linux packaged or pinned tools build, macOS pinned package/artifact, Windows official pinned MAME tools artifact. Confirm each has create/extract DVD commands rather than assuming package name implies support. In that job missing/incompatible decoder is a failure, not a silent skip. Locally the optional integration suite may skip with a clear reason when no path is configured. No dependency installation was performed during this design task.

## Implementation decision gates

CHD is the recommended first provider. CD support is only complete when the generated mixed-track fixture, exact metadata accounting, canonical CUE output, and grouped-cache tests pass. A pure extractraw endpoint is insufficient. Hard native isolation requires either the additional constrained runner or an explicit limitation; do not promise a strict disk sandbox from polling. RVZ/CISO and browser core acceptance remain separately verifiable scope, not implied by registering CHD.
